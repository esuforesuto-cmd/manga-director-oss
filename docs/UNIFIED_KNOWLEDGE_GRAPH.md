# Unified Knowledge Graph Planning

v3.5 candidates organize existing Repository-derived knowledge as graph,
relationship-engine, context, traceability, quality-metric, and insight DTOs.
Every design must state provenance, redaction, ownership, retention, graph
scope, deterministic fixtures, and an explicit no-write proof.

The graph is a projection, not a second database. It cannot persist nodes or
edges, mutate a project, fetch remotely, embed externally, merge knowledge,
repair history, or execute a workflow. See [the v3.5 roadmap](ROADMAP_v3_5.md).
