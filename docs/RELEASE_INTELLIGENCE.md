# Release Intelligence Planning

Release Intelligence candidates aggregate existing release-checklist,
compatibility, regression, package, security, benchmark, and deployment
evidence into dashboard, metrics, deployment-analytics, compatibility-trend,
regression-intelligence, and release-health DTOs.

They must be deterministic, use supplied local evidence, retain release-owner
authority, and never tag, sign, upload, publish, deploy, approve, or alter a
release. Publication remains a deliberate maintainer action after hosted gates.

See [v3.4 roadmap](ROADMAP_v3_4.md) and
[Architecture Planning](ARCHITECTURE_V3_4.md).
