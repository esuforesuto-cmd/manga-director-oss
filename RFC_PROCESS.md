# RFC Process

## When an RFC is required

Open an RFC before proposing a public API, SDK, Extension, Marketplace,
workflow, governance, or deprecation change that is broader than a focused bug
fix.

## RFC format

Include the problem, goals and non-goals, affected public contracts,
compatibility analysis, alternatives, migration or rollback plan, validation
plan, security considerations, and documentation impact.

## Decision process

Maintainers review the RFC for workflow invariants, compatibility, security,
maintainability, and scope. Accepted RFCs authorize an implementation proposal;
they do not automatically authorize release, Marketplace publication, or
workflow execution.
